# Progress

Measured on 2026-11-15 on the development machine: Windows 11, Node 24, pnpm 9.15.9. Every result below comes
from a real run.

## Done

- Monorepo with three apps, eight packages, two workers, one CLI tool and the E2E suite.
  - Apps: `showroom`, `admin`, `api`.
  - Packages: `domain`, `contracts`, `db`, `3d-engine`, `tour-engine`, `ui`, `assets`, plus the
    `tests` package.
  - Workers: `asset-processing`, `render-processing`. Tool: `cad-importer`.
- Demo assets generated by code:
  - six 360 panoramas of Villa 6, with previews;
  - the masterplan GLB with 8 villas;
  - an SVG floor plan, a gallery and a hero image.
- Public showroom: home, 3D masterplan, units, unit sheet, 360 tour, gallery, location map, areas and contact.
- Admin:
  - login, RBAC and organization isolation;
  - CRUD for developments and units, and status history;
  - scenes and the visual hotspot editor;
  - versioned publishing;
  - leads with CSV export, uploads and job review.
- Admin content and accounts (API and screens):
  - development tabs «Galería» and «Ubicación», and floor-plan create/edit/delete in «Plano», with image
    upload (images from an uploaded asset are copied to `published/<org>/`);
  - «Miembros» page, owner only: create, change role and remove, keeping at least one owner;
  - «Mi cuenta» page: password change that revokes older sessions.
  - Invitations by email and password reset by email, with single-use links ([EMAIL.md](EMAIL.md)).
- Kiosk mode for touch screens: idle warning and reset to home, fullscreen, PWA manifest ([KIOSK.md](KIOSK.md)).
- Showroom in Spanish and English: language switch in the header, choice kept in a cookie, `Accept-Language`
  as the fallback (ADR-017).
- Storage drivers local and S3/R2: presigned uploads with a completion check, media behind `MEDIA_PUBLIC_URL`
  ([STORAGE.md](STORAGE.md)).
- Postgres variant of the VM stack with a separate asset worker and daily `pg_dump` + storage backups;
  `/health/ready` and token-protected Prometheus `/metrics` ([BACKUPS.md](BACKUPS.md)).
- Publication diff and rollback: compare any two versions per section; restoring creates a new version that
  keeps current unit status and price (ADR-018).
- Asynchronous ingestion pipeline with manual review. IFC is converted to a GLB of simple volumes per building
  with `web-ifc` and waits for review (ADR-019). DWG, FBX and OBJ are rejected explicitly.
- Lead webhooks for CRMs: owners register URLs under «Integraciones»; each lead is sent signed with HMAC-SHA256,
  retried up to 6 times, with a delivery log in the admin and an https/public-address guard in production
  (ADR-020, [WEBHOOKS.md](WEBHOOKS.md)).
- Tour analytics: the showroom counts views of each unit (sheet or masterplan selection) and each 360 room in
  daily aggregates, skipping visitors with Do Not Track or Global Privacy Control; the admin «Analítica» page
  ranks units and rooms over 7, 30 or 90 days (ADR-021).
- Online reservations with a deposit: «Reservar con señal» on an available unit's sheet opens a form and a
  simulated checkout; an approved payment reserves the unit and records the change, a declined one can be
  retried, and the admin «Reservas» page lists them. No real payment provider is wired (ADR-022).
  Render without a configured backend fails explicitly.
- Engine bugs found during integration and fixed in the engines:
  - double hotspot removal;
  - "Stage not in sync" on fast scene switches;
  - overlapping hidden unit buttons.
  - The app-side workarounds were removed.

## Measured performance

The servers are local production builds (`next start` plus the API). The browser is headless Chromium with
SwiftShader software WebGL, at 1440×900. Each figure is the time from navigation (or click) until the
component reports ready. There were three runs.

| Action | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Open `/masterplan` until the GLB is loaded and the canvas is ready | 847 ms | 941 ms | 1452 ms |
| Open `/tour/villa-6` until the first panorama is ready | 529 ms | 227 ms | 164 ms |
| Switch room (living to kitchen) until the new scene is ready | 57 ms | 152 ms | 101 ms |

The tour page navigation timing was TTFB 7 ms, DOMContentLoaded 26 ms and load 26 ms.

Masterplan times include software WebGL. Expect real GPUs to be faster, but this was not measured.

## Pending and limitations

- Deployed on 2026-11-17 to an Oracle Cloud Always Free `VM.Standard.E2.1.Micro` (x86_64, 1 GB RAM, 4 GB
  swap). The image is built off the VM and copied over. ARM (A1) was never available in `sa-vinhedo-1`. See
  [DEPLOYMENT.md](DEPLOYMENT.md).
- The local Docker test found that the production CSP blocked the masterplan's WebAssembly decoder. Fixed
  with `'wasm-unsafe-eval'` and covered by `tests/e2e/csp.spec.ts`.
- Panoramas are cut into multiresolution cube tiles (512 px tiles, faces 512–4096 px). Scenes created from a
  media URL instead of a processed asset still load the single equirect image.
- Postgres is tested (API suite, seed, backup/restore and an API + worker smoke), but the Postgres compose
  stack was not brought up on the VM. Redis/BullMQ is untested. S3 is tested against local RustFS only.
- The deployed VM has no SMTP configured, so invitations and password resets answer 503 there.
- Not automated: pinch zoom, real GPU rendering, load tests and screen-reader output. See
  [TESTING.md](TESTING.md).
- Only the interface is translated. Content entered in the admin (unit and room names, descriptions, points of
  interest) is shown in the language it was written in.
- The demo data is fictitious. Real panoramas and models from the client are the next improvement.
