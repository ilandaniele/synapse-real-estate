# Progress

Measured on 2026-11-15 on the development machine: Windows 11, Node 24, pnpm 9.15.9. Every result below comes
from a real run.

## Done

- Monorepo with three apps, eight packages, two workers, one CLI tool and the E2E suite.
  - Apps: `showroom`, `admin`, `api`.
  - Packages: `domain`, `contracts`, `db`, `3d-engine`, `tour-engine`, `ui`, `assets`, plus the
    `tests` package.
  - Workers: `asset-processing`, `render-processing`. Tool: `cad-importer`.
- Demo assets generated by code:
  - six 360 panoramas of Villa 6, with previews;
  - the masterplan GLB with 8 villas;
  - an SVG floor plan, a gallery and a hero image.
- Public showroom: home, 3D masterplan, units, unit sheet, 360 tour, gallery, location map, areas and contact.
- Admin:
  - login, RBAC and organization isolation;
  - CRUD for developments and units, and status history;
  - scenes and the visual hotspot editor;
  - versioned publishing;
  - leads with CSV export, uploads and job review.
- Asynchronous ingestion pipeline with manual review. DWG, IFC, FBX and OBJ are rejected explicitly.
  Render without a configured backend fails explicitly.
- Engine bugs found during integration and fixed in the engines:
  - double hotspot removal;
  - "Stage not in sync" on fast scene switches;
  - overlapping hidden unit buttons.
  - The app-side workarounds were removed.

## Measured performance

The servers are local production builds (`next start` plus the API). The browser is headless Chromium with
SwiftShader software WebGL, at 1440×900. Each figure is the time from navigation (or click) until the
component reports ready. There were three runs.

| Action | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| Open `/masterplan` until the GLB is loaded and the canvas is ready | 847 ms | 941 ms | 1452 ms |
| Open `/tour/villa-6` until the first panorama is ready | 529 ms | 227 ms | 164 ms |
| Switch room (living to kitchen) until the new scene is ready | 57 ms | 152 ms | 101 ms |

The tour page navigation timing was TTFB 7 ms, DOMContentLoaded 26 ms and load 26 ms.

Masterplan times include software WebGL. Expect real GPUs to be faster, but this was not measured.

## Pending and limitations

- Deployment files for a single free VM (Docker Compose + Caddy) are ready but not run yet. The Docker image
  was not built locally because Docker Desktop did not start. See [DEPLOYMENT.md](DEPLOYMENT.md).
- Panoramas are single-resolution. Multiresolution tiles are supported by the engine design but not generated.
- Postgres, Redis/BullMQ and S3 are configurable but untested in this session. Everything ran on PGlite and
  local storage.
- Not automated: pinch zoom, real GPU rendering, load tests and screen-reader output. See
  [TESTING.md](TESTING.md).
- The demo data is fictitious. Real panoramas and models from the client are the next improvement.
